# v5.1.11 — Router mengisi placeholder URL (`$vars`) untuk semua method, bukan hanya GET

**Release Date:** 17 Oktober 2026
**Referensi:** Redmine #11043 (SDI) — `sdi_role aksi=ubah` gagal 500 `TypeError authenticate(null)`; analisis akar oleh
Agen Pesut (komentar 17 Okt), diverifikasi di clone `b1253cd`.

---

## 🐞 Masalah

`core/init/route.php` cabang `RouteStatus::FOUND` hanya mengisi `$vars = $routeResult->vars` di cabang `GET`. Untuk `POST`,
placeholder URL (`{role}`, `{privilege}`, `{app}`, …) tidak pernah masuk `$vars`, sehingga konstruktor controller yang
membacanya menerima `null`:

```
POST /gov2login/user/guest   (apps/gov2login/xml/route.xml → gov2login\model\member)
→ apps/gov2login/member.php:12  $self->ses->authenticate($vars['role'])
→ Gov2lib\gov2session::authenticate(): Argument #1 ($_privilege) must be of type string, null given  (HTTP 500)
```

Konstruktor gagal sebelum `update()` sempat jalan, jadi klien tidak bisa mengakalinya lewat body. Dampak yang terlihat:
- MCP gov3sdi `sdi_role aksi=ubah` selalu 500, role tidak berubah (#11043, skenario 4.3 #11006).
- UI portal Pengaturan > Role (`gov2formfield-bs4 :action="/gov2login/user/{role}"`) memakai POST yang sama → simpan
  perubahan role dari browser kena galat yang sama.
- Kode ini berasal dari commit 23 Mei 2025 (`cd567c1`, `0ba6dfe`) — bukan regresi baru.

## ✅ Perbaikan

`$vars = $routeResult->vars` dipindah ke luar cabang method: diisi untuk **semua** method yang cocok rute. Yang lain tetap:
- `POST` tanpa `$_POST` form-encoded tetap mengisi `$_POST` dari body JSON.
- `GET` tetap memberi default `$vars['cmd']` (`""` / `logout`).
- Dispatch `cmd` + payload untuk `POST` tetap diambil dari `$_POST` (`core/init/index.php`), tidak dari `$vars` → tidak ada
  perubahan alur pemanggilan method controller.

## Rute POST ber-placeholder yang kini menerima `$vars` (sebelumnya `null`)

| Rute | Handler | Catatan |
|---|---|---|
| `POST /gov2login/user/{role}` | `gov2login\model\member` | **target perbaikan** — `authenticate($vars['role'])` |
| `POST /gov2login/member/{privilege}` | `gov2login\model\privilege` | konstruktor `authenticate('admin')`, tak membaca `$vars` |
| `POST /gov2option/connection/{privilege}`, `/option/{privilege}`, `/{pageID}/{privilege}` | `gov2option\model\*` | konstruktor hard-code role, tak membaca `$vars` |
| `POST /gov2survey/{app}/*` | `gov2survey\model\*` | konstruktor `authenticate('member')` |
| `POST /{app}/login.php` | `Gov2lib\loginHandler` | konstruktor `checkAppDir($vars["app"])` (param `string`) — kini menerima nama app, bukan `null` |
| `POST /{app}/agendb`, `/{app}/agen` | `Gov2lib\agendbHandler`, `agenHandler` | memakai `$pageID`, tak terdampak |

Tidak ada controller yang bergantung pada `$vars` **kosong** saat POST (grep `global … $vars` di `apps/` dan `core/lib/`),
sehingga satu-satunya perubahan perilaku adalah: nilai yang dulu `null` kini berisi placeholder rute.

## Verifikasi

- `php -l core/init/route.php` bersih; `php8.2 vendor/bin/phpunit --testsuite Unit` → 515 tests, 1556 assertions OK
  (`route.php` prosedural, belum punya unit test; `Gov2lib\Http\Router::dispatch` sudah mengembalikan `vars` untuk POST,
  lihat `tests/Unit/Lib/RouterTest.php`).
- **Belum diuji di server.** Langkah uji di becik/dev setelah deploy:
  1. `sdi_role aksi=ubah email=… role_baru=member` → harap `Operasi UPDATE berhasil`; `aksi=cari` → role berubah.
  2. Browser: login admin → Pengaturan > Role → ubah role satu akun → tersimpan tanpa 500.
  3. Regresi: GET `/gov2login/user/guest`, `/{app}/role/{role}`, login/logout tetap normal.
