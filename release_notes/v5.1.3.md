# v5.1.3 — Fix koneksi MeekroDB tidak berpindah DSN dalam satu request

**Release Date:** 13 September 2026
**Referensi:** Redmine #10801 (deploy SDI staging ke sandbox — panel Instansi kosong)

---

## 🐛 Perbaikan

### `dsnSource`: koneksi MeekroDB ikut berganti saat kredensial DSN berganti

`MeekroDB::get()` memakai ulang `$internal_mysql` selama request walau statik
`\DB::$user/$dbName` sudah diganti oleh `connectDB()` berikutnya. Akibatnya
"connectDB() terakhir menang" hanya berlaku sebelum query pertama.

Kasus nyata (gov2option di portal `sumenepkab.gov3.id`): model memasang DSN domain
(lazy, belum connect) → controller `authenticate('guest')` → `memberRead()` memasang
`master` (`gov3_central`) dan menjalankan query pertama → seluruh query model
berikutnya (`getUnitKerjaList`) berjalan di `gov3_central.instansi` (14.498 baris,
loop N+1) → timeout, panel Instansi kosong. Endpoint tetangga melapor
`Table 'gov3_central.gov2_connections' doesn't exist` walau DSN domain benar.

Perubahan (`core/lib/dsnSource.php`):
- `applyMeekroCredential()` — satu-satunya jalur pemasangan statik `\DB`; bila sudah ada
  koneksi terbuka dengan identitas berbeda (host|port|user|db), `\DB::disconnect()`
  dulu sehingga query berikutnya reconnect memakai kredensial baru.
- `activeCredential()` / `restoreCredential()` — simpan & pulihkan kredensial aktif.
- `credentialKey()` — identitas koneksi (logika murni, password tidak ikut).

Perubahan (`core/lib/gov2session.php`): `memberRead()` dan `memberUpdateCounter()`
memulihkan kredensial aktif sebelum detour `master` (`finally`), sehingga DSN app
yang sudah dipasang model tetap berlaku setelah `authenticate()`. Bila detour
`master` adalah `connectDB()` pertama pada request (kasus #10637), tidak ada yang
dipulihkan — perilaku lama dipertahankan.

Biaya: paling banyak satu reconnect tambahan per request pada app layanan yang
DSN domainnya berbeda dari `master`.
